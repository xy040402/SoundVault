# 音匣 1.0.3 · 波形死循环修复

> 用户反馈：导入 4 个音频后「波形图一直创建不出来」，进度条分子从 4 涨到几万、几十万，永远不结束。

---

## 一、现象

| 项 | 内容 |
|---|---|
| 用户版本 | **1.0.2.0**（日志 `[启动] 1.0.2.0` 可确认） |
| 症状 | `待补=4`，然后 `已完成 76348/4`、`103924/4`、`962621/1615` |
| 结果 | 进度条分子无限增长，界面卡在「正在补齐波形」，只能手动取消 |

---

## 二、根因

### 1. 这 4 个文件其实全是 MP3

包括那个名字叫 `.wav` 的：

```
1. Whoosh Click Loop.wav              codec=mp3  48000Hz 2ch
10. Boomer Knock (Any Key).mp3        codec=mp3  48000Hz 2ch
12. Fast Texture (Any Key) 120bpm.mp3 codec=mp3  48000Hz 2ch
12. Fat Impact (Any Key).mp3          codec=mp3  48000Hz 2ch
```

文件名后缀是假的，内容是 MP3（ID3v2.2 头）。

### 2. 1.0.2 没有任何 mp3 波形分支

`ComputePeaks` 里只处理 WAV / AIFF，mp3 直接返回 `null`；而 `.wav` 那个先按 RIFF 读，
抛 `FormatException: Not a WAVE file - no RIFF header`，同样返回 `null`。

### 3. 算不出来又不落库 → 无限重试

`FillPeaks` 的循环是「取一批 `peaks IS NULL` 的文件 → 算 → 写回」。1.0.2 里失败时**什么都不写**，
于是下一轮 `PeaksMissing` 又把同样 4 个文件取出来，`done` 无限累加：

```
待补=4 → 已完成 76348/4 → 103924/4 → …
```

这就是「分子比总数还大」的原因。

---

## 三、修复

### 1. 按内容判断容器，不看扩展名

```csharp
var kind = AudioProbe.Sniff(path);       // RIFF / RF64 / AIFF / AIFC / Unknown

if (kind is Riff or Rf64)      → WAV 路径（含长文件概略采样）
if (kind is Aiff or Aifc)      → AIFF 路径
否则                            → 解码器（mp3 / flac / m4a…）
```

### 2. 解码器挨个试，谁先成功用谁

NAudio 的 `AudioFileReader` **按扩展名挑 reader**，所以「MP3 改名成 .wav」会走
`WaveFileReader` 并抛 `Not a WAVE file`。改成：

```csharp
try { return new Mp3FileReader(path); } catch (Exception ex) { mp3Error = ex; }
try { return new AudioFileReader(path); } catch { Log.Warn(...); throw; }
```

`Mp3FileReader` 认 ID3 头，改名的文件也能正常解码。

### 3. 失败也要落库（更早的批次已经加过，这里保留）

算不出来就写空数组，`peaks` 不再是 NULL，下一轮不会再被挑出来。

### 4. 失败计数修正

以前把 `null` 替换成空数组**之后**才判断，导致「失败=0」永远显示 0。现在先判后换，
日志能真实反映 `成功=3 失败=1`。

### 5. 防死循环兜底（新增）

即便将来出现别的原因导致写库没生效，也不会再无限刷：

```csharp
var attempted = new ConcurrentDictionary<string, byte>();   // 同一路径只尝试一次
int rounds = 0, maxRounds = Math.Max(8, pending / 50 + 4);

int fresh = batch.Count(p => !attempted.ContainsKey(p));
if (fresh == 0) { Log.Warn("这一批都尝试过了，写库没生效，停止重试"); break; }
if (++rounds > maxRounds) { Log.Warn("轮数超过上限，停止补齐"); break; }
```

## 五、给反馈用户的回复要点

1. 这是 **1.0.2** 的已知问题，1.0.3 起既不再死循环，波形也能正常画出来；
2. 问题文件是 MP3 改了扩展名，新版本按内容识别，不再看后缀；
3. 升级到 **1.0.3** 后重新导入即可，旧索引不用删（扫描会按大小/修改时间判断，不会重复算）；
4. 如果升级后还遇到「分子大于总数」，把 `%LOCALAPPDATA%\SoundVault\logs` 里的日志发来——
   新版会写一句「这一批都尝试过了，写库没生效」或「轮数超过上限」，能直接定位。
