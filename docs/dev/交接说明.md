## 1. 一句话项目状态

**音匣 SoundVault** —— 本地优先的 Windows 音效素材库管理器。当前 **v0.5**，单文件 exe 76.7 MB 已可日常使用：导入素材包 → 悬停试听 → 波形定位 → 拖进 DAW → 批量导出。
v0.5 换了地基：**启动不再遍历素材**（SQLite 索引，1 万文件热启动 706 ms），**波形不再重算**（峰值缓存进 BLOB），**列表只建可见卡片**（虚拟化）。
剩下的是"更好看 + 更顺手"，清单在 `未完成清单.md`（55 条，第 1/2/3/4/7/9/11/19/30/31/32 条已打 ✅）。
v0.5.1 补了导航：**面包屑像资源管理器一样逐级可点**（根目录只显示库名），**左栏是真正的树**——右边点进子文件夹，左边会逐层展开并高亮；**快捷入口与左栏互斥**（同一时间只有一处高亮），「最近导入」改成真的按修改时间倒序，「收藏」改成全库范围，并补齐了 5 种空态。
v0.6 补了"组织"：**标签**（右键打标、卡片上直接显示、左栏一点即筛）、**右键菜单**（收藏/评分/标签/复制路径/在资源管理器显示/导出）、**过滤语法**（`#tag` `star:>=4` `dur:<2s` `sr:>48k` `ch:2` `type:wav`）、**智能文件夹**（保存搜索成左栏入口）、**拼音搜索**（`bdxx` → 拔刀相向）。v0.7 把"看不见"的问题修了：**标签做成带框的小按钮**（卡上显示「＋ 标签」）、**星星加大加亮且整条可点**、搜索框加「?」语法说明；**列表视图已按用户要求删除**（看不到波形，没有意义）。v0.8 又加了**独立标签页**（左栏快捷入口第 4 项）：所有标签集中改名 / 删除 / 合并，点一行就筛这个标签。

## 3. 构建与发布（照抄即可）

```powershell
# 调试构建
cd 'src\SoundVault.App'
dotnet build -v q --nologo

# Release（性能验收必须用这个，Debug 会慢 5–10 倍，别拿 Debug 数字下结论）
dotnet build -c Release -v q --nologo

# 发布单文件（dist\音匣.exe，约 76.7 MB）
dotnet publish -c Release -r win-x64 --self-contained `
  -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -o 'dist'
```

发布后 `dist\SoundVault.App.exe` 是本体，复制成 `dist\音匣.exe` 交付。**正在运行的文件无法覆盖**，先 `Get-Process 音匣,SoundVault.App | Stop-Process -Force`。

`e_sqlite3.dll` 是原生库，靠 `IncludeNativeLibrariesForSelfExtract=true` 打进单文件并自解压——**这个参数不能去掉**，否则发布出来的 exe 一启动就崩（已实测可用）。

## 5. 不可破坏的不变量（踩过的坑，别再来一遍）

1. **时间轴 = 文件真实时间。** 播放头、点击定位、时间码全部按文件毫秒算；`TrimStart/TrimEnd` 只是"循环区间"，不是坐标系。
2. **三种鼠标行为必须分开：** 悬停 = 试听；单击 = 只选择（含 Ctrl/Shift）；**双击 = 固定播放**。曾把单击做成固定，导致"Ctrl 多选后声音停不下来"。
3. **循环默认整段，`trimSilence: false`。** 自动裁静音曾被用户否掉（感觉素材被截短）。智能模式只能作为可选项。
4. **单次播放靠两层保证：** Provider 读到末尾返回 `0` **且** 触发 `Ended` 事件；不能只依赖 WASAPI 是否因读空而停（实测它不停）。
5. **波形几何用 `FillRule.Nonzero`**，柱数按像素宽度降采样（约 1.6px 一根）。用默认 EvenOdd 会把重叠柱异或成"空心鱼骨"。
6. **播放头用 `CompositionTarget.Rendering` 驱动**，禁止 `DispatcherTimer(50ms)`（20fps 肉眼卡）；进度条用 `ScaleTransform`，禁止改 `Width`（会触发整条布局管线）。
7. **颜色 token 语义严格：** `Divider` 画线、`PanelBorder` 画面板边、`PillHoverBg` 画悬浮底色、`OverlayBg` 画"浮在内容上必须不透明"的层。曾用 PanelBorder 画分隔线，深色碰巧正常、浅色直接看不见。
8. **所有弹出物都要自定义模板**：ContextMenu / MenuItem / Separator / ToolTip / MessageBox —— 系统默认是白底方角，在深色界面里非常刺眼。
9. **拖拽载荷必须是 `DataFormats.FileDrop` 的真实路径数组**，否则 DAW 不认。
10. **发布参数别改**（SingleFile + 压缩 + `IncludeNativeLibrariesForSelfExtract`）；改文件名没问题（`音匣.exe` 就是复制出来的）。
11. **★ 虚拟化面板必须放在 `ListBox` 里，不能放 `ItemsControl` + 外层 `ScrollViewer`。** `ScrollContentPresenter` 只会把 ListBox 模板里的 `ScrollViewer` 跟面板挂钩；`ItemsControl` 那样写 `ScrollOwner` 永远是 `null`，滚动范围塌成"一屏"，用户根本翻不到第 2 页（v0.5 踩了，已修）。
12. **列表项容器必须清空样式**：`ListBoxItem` 默认模板自带白底蓝框，会把卡片糊掉；`App.xaml` 里那段 `ItemContainerStyle`（纯 `ContentPresenter` + `Focusable=False`）不能删，删了空格键还会被 ListBox 吃掉。
13. **整批换列表用 `RangeObservableCollection.ResetWith`**，不要逐条 `Add`：1 万条逐条发 `CollectionChanged` 会卡住 UI 线程好几秒。
14. **增量扫描的"清理"必须在同一个事务里**：先把本次见到的路径灌进临时表，再 `DELETE ... NOT IN`。中途取消就整体放弃，**绝不能在没扫完时删行**，否则一次 Esc 会把索引删空。
15. **★ 导航只有一个入口：`NavigateTo(node)`。** 面包屑、左栏行、右栏文件夹卡片全部走它，它会顺手把左栏的祖先逐层展开并选中（`SyncSidebarSelection`）。**别再写第二套跳转**，否则就会出现"右边点进去、左边不亮"这类不同步。
16. **★ 左栏三角（`Chevron_Click`）只折叠，不导航**：必须 `e.Handled = true`，否则 `ListBoxItem` 会把它当成选中 → 打开文件夹。命中区要给 `Border Background="Transparent"`，光给 `TextBlock` 的话只有几个字能点中。
17. **★ 面包屑是代码生成的**（`ShowCrumbs` + `TrailFor`），不是 XAML 里写死的两个 TextBlock。根目录只有一段（库名），不可点；子文件夹每段加一个 `CrumbBtn` 样式的 Border。
18. **左栏树是"懒加载 + 平铺"**：`FolderItem.Children` 用 `EnsureChildren` 按需枚举一层；`_side` 是"可见节点"的平铺列表（`RebuildSidebarCore`）。**载入子级或改变展开状态后必须重建 `_side`**，否则会出现"三角是展开的、子项却没显示"。
19. **★ 左栏层级只靠 `FolderItem.IndentMargin`（`Depth * 16`）**：库节点 = 0，一级 16、二级 32…… 不要再写"库 margin=0 / 文件夹 margin=18"那种硬编码——加了三角列之后会把两级挤成一样深（v0.5.1 踩过，视觉上"树没了"）。
20. **★ 同一时间只允许一处"亮"**：快捷入口（全部音效/收藏/最近导入）与左栏树互斥。进树节点时 `ClearQuickSelection()`，进快捷视图时 `ClearSidebarSelection()`，两边都有 `_suppressXxx` 防递归。当前视图种类记在 `ViewKind` 枚举里（Library/All/Recent/Favorites/Folder），`ReloadCurrentView` 按它分派——**别再想着用 bool 描述视图了**。
21. **★ 键盘焦点必须落在窗口上**：WPF 激活窗口时会把焦点交给第一个可输入元素（搜索框），那样空格 / F / 1-5 就变成打字，用户会报"快捷键没反应"。已经做的是：标题栏按钮、左栏两个列表全部 `Focusable="False"`；启动和鼠标点内容后 `FocusKeyboard(true)` 强制收回；键盘处理改挂在 **`PreviewKeyDown`**，并且当焦点在 `TextBox` 里时只放行 Esc。
22. **★ 产品硬规则：所有功能必须有鼠标路径。** 用户明确要求"大多数功能不要用到键盘"。评分/收藏已经是卡片上的实体控件；新增任何功能，先问"鼠标能不能做到"，键盘只作为加速器。**这台机器上键盘实测完全无响应（原因未查明），不要依赖它验证任何东西。**
23. **★ 收藏/评分在卡片上有实体控件**
- 收藏：`heartBtn`（Segoe MDL2 `EB51`/`EB52`），绑 `AssetItem.HeartGlyph`，永远可见。
- 评分：`controls/StarRating.cs` 自绘 5 星（一个元素搞定，别用 5 个 TextBlock——会拖慢滚动），`StarClicked` 路由事件回到 `Star_Click`，再点同一颗 = 清零。：`heartBtn`
23. **★ 标签存在 `index.db` 里，按绝对路径关联**（跟 store.json 的评分/收藏一致）：`tags` 与 `asset_tags` 两张表。**读标签一定用 `TagsByPath(一批路径)`**，别一张卡查一次库。
24. **★ 左栏现在有三组可选项：快捷入口 / 智能文件夹 / 标签，加上树。同一时间只允许一处"亮"**：`ClearQuickSelection` / `ClearSidebarSelection` / `ClearSearch` 会互相清理；点标签后 `TagList.SelectedIndex = -1`；只有"点智能文件夹"这条路径允许它自己保持高亮（用 `_applyingSmart` 标记）。
25. **★ 右键菜单在代码里构建**（`BuildAssetMenu`），条目全部走已有的 `ToggleFavorite / SetRating / ToggleTag`，不要再写一套。
26. **★ 没有列表视图（用户明确否决）**：面板里的 `FullRowMode` 还留着（一行一个虚拟化项的实现），但 UI 上已删干净，别再往工具栏加切换按钮。
27. **★ 一个路径只能是"一个库"**：`AddLibraryNode` 会拒绝登记"已经是某个库的子目录"的路径，`IndexDb.RepairNestedLibraries()` 启动时把历史错行归回库根。否则那些文件会从全部音效/搜索里凭空消失（v0.16 修过真实案例：少 13 个）。
28. **★ 外层 ScrollViewer 套 ListBox 时，滚轮会被内层吃掉**：必须在**外层**挂 `PreviewMouseWheel` 自己滚并 `e.Handled = true`（左栏已这么做）。只靠默认冒泡，鼠标滚轮在列表上就是死键。
28. **★ 代码里生成的控件别用 `FindResource` 取颜色**：换主题时字典换了，但这些控件还拿着旧画笔（浅色模式白字白底就是这么来的）。要用 `SetResourceReference(ForegroundProperty, "TextPrimary")`。
29. **★ 面板叠层色不能写死**：`SurfaceTheme` 的基准色必须从**当前主题**里取（`SetBaseline`），深色主题用白色叠层、浅色主题用墨色叠层。写死白色会让浅色模式所有边框消失（v0.18.2 修过）。
30. **★ 网格列宽必须"平分可用宽度"**：`VirtualizingWrapPanel` 的格子宽是 `vw / 列数`，不是固定的 `CellWidth`（那只是最小卡宽阈值）。固定宽会在右边留空档，而且卡片模板必须 `HorizontalAlignment="Stretch"` 才跟着撑开（v0.18.5）。
### 主题 token 语义（#54：避免"既当高光又当线"）

| token | 含义 | 不要拿它做 |
|---|---|---|
| `WindowBg` | 窗口底色 | 面板背景 |
| `PanelBg` | 面板/侧栏底色（半透明叠层） | 卡片背景 |
| `PanelBorder` | 面板**边框**（细线） | 高光/选中 |
| `CardBg` / `CardHover` / `CardBorder` | 卡片三态 | 面板 |
| `Accent` / `AccentSoft` / `AccentBorder` | 强调色：主色、柔和填充、边框 | 正文文字 |
| `OnAccent` | 画在强调色上的文字/图标 | 普通文字 |
| `TextPrimary` / `TextSecondary` / `TextTertiary` | 正文 / 次要 / 提示 | 边框 |
| `Divider` | 分隔线 | 边框（有 1px 语义差异） |
| `PointerGlowBrush` | 鼠标光晕（深浅色各自一套） | 其他高光 |
| `WavePlate` / `Wave` / `WavePlayed` | 波形底板 / 未播 / 已播 | 其他 |

约定：
- **代码生成的控件不要用 `FindResource` 取颜色**，用 `SetResourceReference(...)`，否则换主题后还是旧颜色；
- **面板叠层色的基准来自主题**（`SurfaceTheme.SetBaseline`），不要在代码里写死白色；
- 新控件优先复用上面这些 token，不够就**新增语义明确的 key**，不要借用相邻含义的。
31. **★★ 任何"改磁盘"的验收钩子必须有路径白名单**：`SV_RENAME_TEST` 只允许 `D:\sv-` 开头的临时库。事故记录：v0.19 时钩子误对真库改名 3 个文件（因为测试 store 被运行中的进程覆盖），已按文件大小核对恢复。**写测试配置前必须先确认进程退出**。
32. **★ 自绘 Slider 模板必须给根 Grid 铺 `Background="Transparent"` + 开 `IsMoveToPointEnabled`**：否则只有 4px 轨道线能点、点轨道也不跳，用户会觉得"这个滑杆坏了"（v0.13.1 修过）。
28. **★ 无边框窗口的最大化由 `WM_GETMINMAXINFO` 接管**（`MainWindow.WndProc`）：把 `ptMaxSize/ptMaxPosition/ptMaxTrackSize` 压到 `rcWork`。删掉这段，最大化就会盖住任务栏、底部播放条被吞掉——这是 v0.9.1 修过的真实 bug。
28. **★ 内容区网格：只有给某一行 `*` 高度，跨行（`Grid.RowSpan`）的元素才看得见**。标签页空白过一次——两行都是 0 高，`RowSpan=2` 的 ScrollViewer 高度也是 0。`ApplyContentLayout(..., showTags: true)` 会强制留一行 `*`。
28. **★ 每张卡底部那行标签就是入口**：`TagDisplay` 在没有标签时返回「＋ 标签」，`TagLine_Click` 直接弹标签菜单。别把它改回纯文本——那是 v0.6 用户"找不到标签功能"的直接原因。
29. **★ `FindResource("Transparent")` 会抛异常**：`Transparent` 是 XAML 关键字不是资源键，代码里要用 `Brushes.Transparent`（v0.6 因此崩过一次，见《开发记录》§19）。
29. **行内的 `RowDefinition x:Name` 用来切布局**：内容区第一行是文件夹卡片条（根视图占满 / 文件夹里最多两行），第二行是音效网格（`ApplyContentLayout`）。新增视图时记得同时设行高和 Visibility。

### 截图（关键：DPI 感知 + 别抢焦点）

这台机器是 **150% 缩放**。用普通 PowerShell 截图会得到虚拟化坐标，画面会错位。三种脚本都在 `.scratch\`：

| 脚本 | 用途 | 特点 |
|---|---|---|
| `cap.ps1 -Out x.png` | 前台截图（`CopyFromScreen`） | 需要窗口在最前；**会抢焦点** |
| `capp.ps1 -Out x.png` | ★ 后台截图（`PrintWindow` + `PW_RENDERFULLCONTENT`） | **不抢焦点**，窗口被盖住也能截；优先用这个 |
| `uisel.ps1 -SelectRectX -SelectRectY` | 用 UIA 选中侧栏项（不点鼠标） | 配合 `capp.ps1` 可全程不打扰用户 |
| `crop.ps1 -In -Out -X -Y -W -H -Scale 2` | 局部放大（查 1px 级视觉问题） | 缩略图看走眼时用 |
| `cap.ps1` 里的 `RECT/Cap` 类 | DPI 感知（`SetProcessDPIAware`） | **必须在截图前调用** |

- 窗口实际是 **1920×1200 实像素**，位于大约 (320,164)；`capp.ps1` 会自己读 `GetWindowRect`。
- **用户可能正在玩游戏/看视频**：全屏游戏会抢走前台，`CopyFromScreen` 会截到游戏画面。这时只用 `capp.ps1`/`uisel.ps1`，不要用 `SetForegroundWindow`。
- 弹窗（MessageDialog）是独立窗口，用 `GetForegroundWindow()` 拿它的 rect 截。
- **UIA 里 `AutomationId` = XAML 的 `x:Name`**：可直接读 `PlayerLabel` / `ContentStat` / `PlayIcon` 做断言，比看截图可靠。

## 9. 当前数据层（v0.5：两套存储，职责分开）

| 存什么 | 在哪 | 什么时候写 | 备注 |
|---|---|---|---|
| 库列表 / 评分 / 收藏 / 主题 / 音量 / 设备 | `%LocalAppData%\SoundVault\store.json` | 用户操作后立刻 `Save()` | **用户数据，不要动**；路径是 key |
| 文件元信息 + 波形峰值 | `%LocalAppData%\SoundVault\index.db` | 增量扫描后一个事务写入 | **可随时删除**，删了下次启动重建（213 文件 0.7 s / 1 万文件 2.1 s） |

```json
// store.json
{ "Libraries": ["H:\\音效库\\..."],
  "Assets": { "<绝对路径>": { "Rating": 0, "Favorite": false } },
  "Theme": "dark", "Volume": 0.85, "Normalize": false, "DeviceId": null }
```

```sql
-- index.db 只有两张表
CREATE TABLE meta(key TEXT PRIMARY KEY, value TEXT);                -- schema 版本
CREATE TABLE files(
  id INTEGER PRIMARY KEY, lib TEXT, dir TEXT, name TEXT, path TEXT UNIQUE, ext TEXT,
  size INTEGER, mtime INTEGER,            -- 增量比对用（大小 + 最后写入时间）
  sr INTEGER, ch INTEGER, bits INTEGER, dur REAL,
  peaks BLOB,                             -- 512 点、0–255 量化、8 bit/点
  ok INTEGER                              -- 0 = 头解析失败（界面显示"无法解析"）
);
-- 索引：ix_files_lib / ix_files_lib_dir / ix_files_name
```

**启动流程（改这块前务必读懂）**

1. `IndexDb.Open()` → 读 `store.json` 的库列表 → `AddLibraryNode()` 用**索引里的计数**把侧栏和文件夹卡片画出来（不碰文件系统，毫秒级）。
2. `ScanLibrariesAsync()` 后台跑 `Indexer.ScanAsync()`：枚举目录 → 跟 `Stamps()` 比对 → 只对"新增/变了"的文件并行读头+算峰值 → 一个事务 `ApplyScan()`（含删除已消失的文件）。
3. 扫描结果 `Added+Changed+Removed > 0` 才刷界面；**为 0 时什么都不重画**，所以热启动完全不闪。
4. 进文件夹/全库都走 `_db.FilesInDir / FilesUnderDir / FilesUnder`，波形直接来自 `Peaks` 列（`AssetItem.Wave` 是惰性解码的，只有卡片被实体化时才建）。

**已知取舍**

- 非 WAV 格式（mp3/flac…）能播放（NAudio）但**算不出峰值**（头解析只认 RIFF）→ 显示"无法解析"。要做的话得接 NAudio 解码算峰值（清单里没有单列，归到"元数据读取"附近）。
- 文件被移动/改名 = 旧行删除 + 新行插入，评分/收藏按路径存，所以会丢（这是清单第 13 条"文件丢失/重连"要解决的）。
- 索引库损坏时不要慌：`MainWindow.OnLoaded` 里有 `try/catch`，打不开就退回"每次现场枚举"的旧模式，不会启动失败。
