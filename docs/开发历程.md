## 阶段一：立项 — 从一句话到 12 章设计文档

### 你给的原始需求

> 左边列表、右边大区域显示音效；非叶节点显示子文件夹，叶节点显示全部音效；右边直接画波形图；整个素材包文件夹可以拖进左边栏自动导入；鼠标悬停自动循环播放；按住能拖进 DAW；浅色/深色主题，主色支持 RGB/HEX/HSV 自定义。

### 我补的 6 条（都是你没想到但会立刻踩到的）

| 补充 | 不补会怎样 |
|---|---|
| 悬停 **140ms 防抖 + 移出即取消** | 鼠标扫过一排卡片就是"机关枪"，响成一片 |
| 循环的**接缝处理** | 96 kHz 素材在循环点会"啪"一声 |
| 拖拽载荷必须是 **`CF_HDROP`** | DAW 只认真实文件路径，别的格式全废 |
| **峰值缓存** | 6400 个 96k 文件不可能实时解码画波形 |
| **性能预算**（玻璃 ≤2ms/帧、模糊面板 ≤3 个） | 玻璃材质最容易把 60fps 搞崩 |
| **支持边界**：只支持能解码的音频，不碰 Kontakt/UVI 容器 | 否则宣传和实际不符 |

### 三个技术决定

| 决定 | 选择 | 理由 |
|---|---|---|
| 框架 | **.NET 10 + WPF 原生** | 原生 `DoDragDrop`（DAW 拖拽唯一可靠路径）、WASAPI 低延迟、单文件 exe |
| 音频 | **NAudio + WASAPI 共享模式 + 自写循环 Provider** | 采样级循环、设备可选、96k→48k 重采样 |
| 索引 | **SQLite** | 万级查询毫秒级、可增量更新 |

### 一个诚实的取舍：玻璃

你说的是"液态玻璃 + 毛玻璃"。WPF 里做真模糊最容易翻车，所以拆成三层按风险排序：

| 层 | 做法 | 结果 |
|---|---|---|
| L0 底板 | Windows 11 Mica | 后来做了（v0.14） |
| L1 霜面 | 降采样 + BlurEffect | **没做**（成本高、收益低） |
| L2 液态 | 半透明 + 边光 + 指针高光（**不模糊**） | 做了 |

> 一直没假装"毛玻璃"是真的 —— 到 1.0.0 它仍是视觉近似。

**产出**：《设计文档.md》12 章 + 3 附录、《界面线框.html》9 节可交互线框。

| 阶段 | 做了什么 | 卡住的地方 |
|---|---|---|

| **接线** | 把"能看不能点"的控件全部接上 | 大量空按钮 |

> 这一阶段最重要的一条经验：**先让它跑起来，再让它好看**。
> M0 的界面丑得没法看，但证明了技术栈可行 —— 这比先做三天 UI 再发现拖拽不行要省太多。

## 阶段七：v0.42 → v0.58 — 安装器、卸载器、以及一次事故

这一段几乎全部是**你实际用出来才发现的问题**：

| 版本 | 你报的现象 | 真正的根因 |
|---|---|---|
| v0.42 | 选 `D:\Apps` 结果一堆文件散在根上 | 安装路径没补 `SoundVault` 子目录 |
| v0.43 | 安装没有读条、没有完成提示 | 装到 Program Files 时**走了静默安装**，把 UI 跳过了 |
| v0.43 | 为什么安装包里有**叮咚社的音效**？ | 代码里**硬编码**了你的素材包路径 `H:\音效库\叮咚社…`，全新安装会自动加库 → 已彻底删除 |
| v0.44 | 装新版不检测旧版 | 升级流程重做：检测运行中 → 提示关闭；检测旧版在别处 → 提示先卸载 |
| v0.47 | 装到 Program Files 还是没进度条 | **三个 bug 叠加**：提权走静默 + `StartupUri` 双窗口 + `Application.StartupUri = null` 抛异常 |
| v0.48 | 右上角 X 比其他按钮小一圈 | 我之前误改模板留下了 `Padding="10,6"` |
| v0.49 | 设置左边的钉子没功能 | 它一直是个 `IsEnabled="False"` 的**占位按钮** |
| v0.53–55 | 卸载完点 X/完成没反应、卸不干净、双击卸载变安装 | ① `_running` 没重置 ② 双击无参数走安装分支 ③ Program Files 里卸载器没权限删自己 ④ 收尾清理抢跑 |
| v0.56 | 集合完全编辑不了 | 右键事件挂在 `MouseRightButtonDown`，被 ListBox 吃掉 |
| v0.57 | 点了集合再点别的，**两个高亮** | 左栏是四个独立 ListBox，互不清选中 |
| v0.58 | — | Logo：波形匣 |

### ⚠️ 我造成的真实数据丢失

测试 v0.52 卸载时，我用**盲点坐标**去点按钮：第一下落在了「同时删除软件数据」复选框上（勾上了），第二下才点到卸载。

结果：**你真实的 `%LocalAppData%\SoundVault` 被删除** —— 2 个库、8 个集合、评分和标签。

抢救：从 22:51 的 `backup\data-卸载前\` 恢复 `store.json`，索引重新扫描。
**没救回来的**：Weaponiser 库记录、7 个集合、部分评分。

**这件事之后立的规矩**：

1. 破坏性 UI 一律 **UIA 找元素、读名字再点**，禁止盲点坐标
2. 提权窗口 UIA 读不到时，用**提权助手脚本**操作，或者干脆让你自己点
3. 测试卸载/删数据之前，先把你的数据完整备份到别处

> 这条必须写进文档：**自动化测试能验证功能，也能一夜之间删掉用户的数据。**
> 后者只需要一次"我觉得这个坐标应该是对的"。

## 犯过的错（全部留档）

| 错误 | 后果 | 现在的做法 |
|---|---|---|
| 盲点坐标点卸载 | **删了你真实的数据** | 破坏性操作一律 UIA 读名字再点 |
| 硬编码 `DemoPack` 路径 | 全新安装会自动加你的库 | 彻底删除，首次启动是空状态 |
| `Application.StartupUri = null` | 抛 `ArgumentNullException` | 从 `App.xaml` 删掉 StartupUri，窗口全在代码里建 |
| 安装器提权走 `--silent` | Program Files 安装**没有 UI** | 改成 `--elevated` 重开完整窗口 |
| WPF 子菜单缺 `PART_Popup` | 评分/标签/加入集合**三个子菜单不弹** | 菜单模板补 `PART_Popup` |
| 用文本替换改代码 | 缩进/换行不匹配，**静默不改**，还改坏过几次 | 整段重写方法，改完 grep 回读验证 |
| PowerShell `$h` 与 `$H` 撞名 | UIA 连不上窗口，排查很久 | 变量名一律带前缀 |
| `.ps1` 存成无 BOM 的 UTF-8 | 中文被按 ANSI 读，**语法错误** | 本项目所有 `.ps1` 一律 **UTF-8 with BOM** |
| 中文文件名上传 GitHub | 被转义成 `v1.0.0.exe` | 发布附件用英文名 |

## 给"第一次完整做一款软件"的 10 条

1. **先跑起来再好看**。M0 丑得没法看，但它证明了技术栈；先做 UI 的话，三天后可能发现"拖拽根本不支持"。
2. **写下你的验收标准**。每个版本我都写"操作 → 实测结果"的表格，没有表格的版本不算完成。
3. **冻结一个版本**。v0.38 之后所有改动都在新号下，出问题有参照物。
4. **真正的 bug 都藏在"应该是这样"里**。集合编辑不了、两个高亮、安装没进度条 —— 全是我以为对的地方。
5. **别人的一句话，可能是三个 bug 叠加**。"装到 Program Files 没进度条"背后是提权、双窗口、非法 null 三个问题。
6. **不要盲点坐标**。我用一次盲点删掉了用户真实数据，这个教训值 8 个集合。
7. **文档不是负担**。76 节开发记录让我在 20 小时后还记得"为什么这里要 140ms 防抖"。
8. **能拆就拆**。`MainWindow` 拆成 partial、逻辑抽成 ViewModel，所以 v0.30.1 砍功能只花了几分钟。
9. **诚实标注没做的**。毛玻璃只是近似、签名还没证书、跨平台不做 —— 写在文档里，比被用户发现强。
10. **发布也是功能**。安装器、卸载器、数据保留策略、README、License —— 用户第一次接触到的不是代码，是安装包。
