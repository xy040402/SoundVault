# 反馈与支持

## 遇到问题，先做这两件事

**1. 打开日志看一眼**

```
%LocalAppData%\SoundVault\logs\app-20260101.log
```

音匣从 v1.0.1 起会记日志：启动环境、导入、扫描（含每个阶段的耗时）、解码失败、播放失败、导出、重命名、删库。
文件名按日期，一天一个，单个 5 MB 满了自动换。

**2. 导出诊断包**

音匣 → 右上角齿轮「设置」→ **导出诊断包…** → 得到一个 zip，里面是：

| 内容 | 用途 |
|---|---|
| `logs/*.log` | 出问题时那几行 |
| `system.txt` | 版本、Windows、.NET、CPU、内存、屏幕、数据目录 |

注意：诊断包里**不含**你的音效文件名和路径（隐私考虑），如果问题跟具体文件有关，请单独说明。

## 到哪里说

| 目的 | 去哪里 |
|---|---|
| 有东西坏了、表现不对 | [新建「问题反馈」](https://github.com/xy040402/SoundVault/issues/new?template=bug_report.yml) |
| 希望多一个功能 | [新建「功能建议」](https://github.com/xy040402/SoundVault/issues/new?template=feature_request.yml) |
| 已经有人提过 | 在 issue 里补充"我也遇到 + 我的版本/系统"就够，不用再开一条 |
| 只是想说说用法 | 在任意相关 issue 下留言都行 |

**为什么不开 QQ 群 / 微信群**

- 群里的答案搜不到，后来的人得再问一遍
- 同一个问题会被问十次，回答的人会烦
- GitHub issue 能挂日志、能贴截图、能搜、能被别人看到

真需要实时聊的，issue 里说一声就行，我会回。

## 写反馈时请带上

| 项 | 为什么要 |
|---|---|
| 版本号 | 不同版本行为不一样（设置面板顶部） |
| Windows 版本 | 解码、毛玻璃、安装权限都跟它有关 |
| 怎么操作的 | "点导入就崩了" 定位不了，需要顺序 |
| 期望 vs 实际 | 有时是设计如此，说清楚才知道要不要改 |
| 日志或诊断包 | 90% 的问题这里能直接看出来 |

## 已知限制（不是 bug）

- 插件专有容器（Kontakt `.nki/.ncw`、UVI `.ufs`）不是音频文件，读不了
- macOS 版暂时没有
- 百万级文件的库还没优化到位，v1.1 会做两阶段索引
- 安装包没有代码签名，首次运行 Windows 可能提示"未知发布者"——点"更多信息 → 仍要运行"
