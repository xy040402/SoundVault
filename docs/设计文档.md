## 0. 一页读懂

| 问题 | 答案 |
|---|---|
| 是什么 | Windows 桌面音效素材库管理器。单 exe，双击即用，本地优先，零订阅。 |
| 给谁用 | ① 影视/游戏音效设计 ② 独立视频/短剧创作者 ③ 音乐制作人（采样/loop） |
| 凭什么赢 | ① 拖入即入库，无向导 ② 悬停即无缝循环试听 ③ 按住即拖进 DAW ④ 液态玻璃材质界面 ⑤ 中文素材包命名习惯的深度适配 |
| 怎么实现 | .NET 10 + WPF 原生，SQLite 索引，WASAPI 播放，DWM 材质 + 自绘霜面 |
| 交付形态 | 单文件 exe（约 70–90 MB，自包含运行时，无需管理员权限），另提供安装版与便携版 |
| 你的库跑得动吗 | 实测 217 个文件 / 1.33 GB（叮咚社古风 4.0），首次索引约 10–20 秒；万级库目标 <3 分钟 |

**设计主张（一句话）**：把"找声音"这件事压缩到三次动作 —— 键入、看见、拖走。

## 1. 市场与竞品

### 1.1 三类用户，三种痛点

| 用户 | 现状 | 痛在哪 |
|---|---|---|
| 音效设计师（专业） | 手里 5–50 个商业库，几十万个文件 | 找不到"那一个"；元数据与分类体系不统一；和 DAW 之间来回切 |
| 独立创作者（半专业） | 买了几套素材包，靠文件夹翻 | 不知道库里有什么；试听要一个个点；格式杂、命名乱 |
| 音乐制作人 | 采样包 + loop | 要节奏感试听；要快速拖进 FL/Studio One |

三者的共同点：**素材是资产，但取用成本高**。谁把取用成本降到接近零，谁就赢。

### 1.2 竞品拆解

| 能力 | Soundly | Soundury | Eagle | 音匣 v1 目标 |
|---|---|---|---|---|
| 本地库索引 | ✅ 声称支持 wav/aiff/mp3/m4a/ogg/flac，≤384kHz/32bit | ✅ | ✅（通用素材） | ✅ wav/aiff/mp3/flac/m4a/wma/ogg |
| 波形显示 | ✅（含频谱图） | ✅ | ✅ | ✅ 多级峰值缓存，96k 秒开 |
| 悬停自动循环试听 | — | — | — | ✅ **核心差异点** |
| 拖到 DAW | ✅ 官方集成 Pro Tools/Logic/Premiere/Nuendo/Cubase/Reaper/AE/Wwise/FMOD | ✅ | ⚠️ 通用文件拖拽 | ✅ 原生 CF_HDROP，实测 FL/S1/Cubase |
| 元数据编辑 | ✅ 侧栏编辑 + UCS | ✅ UCS + 自定义字段 | ⚠️ 弱 | ✅ BWF/iXML/UCS + 通用 KV |
| 语义搜索 | ✅ 自然语言 + 翻译 | ✅ AI 中文搜英文素材 | ❌ | 🅿️ P2（中文拼音/关键词先用） |
| 标签 / 评分 / 收藏 | ✅ Collections | ✅ Tag | ✅ 强（智能文件夹/筛选器） | ✅ |
| 云端素材库 / 商店 | ✅ 25 万条 | ❌ | ❌ | ❌ 明确不做 |
| 界面材质化 | ❌ 平面深色 | ❌ 平面深色 | ❌ 平面深色 | ✅ **液态玻璃** |
| 价格 | 免费版限 1 万本地文件；Pro 订阅 | 399–799 元 | 买断 | 买断/免费（待定，§12） |
| 启动 / 内存 | 重（Electron 系） | 中 | 中 | 轻：<1.5s / <400MB |

> 竞品信息来自各自官网与公开报道，用于定位参考，不作为功能承诺依据。

### 1.3 空位在哪

三条轴拉出来看：**重云端 ←→ 纯本地**、**付费订阅 ←→ 买断**、**平面 UI ←→ 材质化 UI**。

- Soundly 在"云端 + 订阅 + 专业集成"这一角，强，但贵、重、必须联网（离线版另售）。
- Soundury 在"中文 + AI 搜索"这一角，新锐，但仍是平面 UI、付费门槛。
- Eagle 在"通用素材 + 买断"这一角，但它不是音效工具 —— 没有循环试听、没有采样率概念、没有 DAW 拖拽优化。

**空位**：本地优先 + 零订阅 + 材质化界面 + 精专音频交互。这正好是个人创作者和中小工作室的主场。

### 1.4 差异化主张（5 条，可验证）

1. **零等待**：拖入 217 个文件，30 秒内可试听；冷启动 1.5 秒。
2. **零误触**：悬停播放带 140ms 防抖与取消规则，快速划过不"机关枪"。
3. **零切换**：置顶 + 全局热键，DAW 在前台也能唤出、试听、直接拖进去。
4. **零门槛**：不建库、不导向导、不填元数据也能用；元数据是加分项不是前置条件。
5. **不糊脸**：玻璃材质有硬性对比度下限和"实心模式"，不是为好看牺牲可读性。

## 2. 产品定义

### 2.1 定位

> **音匣**是一个"把硬盘变成本地搜索框"的音效库工具。它不生产声音，只让你在 10 秒内找到并拿走你要的那一个。

### 2.2 用户画像

**A. 阿哲 · 影视音效师（主力用户）**
- 8 块硬盘，约 30 万文件，常用 Cubase/Nuendo
- 需要：多库管理、UCS 分类、BWF 元数据、快速 A/B、批量交付
- 判定成功：一次找声音平均 <20 秒

**B. 小林 · 短视频创作者（增长用户）**
- 买了 3 套古风/武侠素材包，共 2000 个文件，用 Studio One
- 需要：知道库里有什么、试听快、拖一下就到时间线
- 判定成功：装完 5 分钟内没有打开帮助文档

**C. 阿凯 · 音乐制作人**
- 采样包 + loop，用 FL Studio
- 需要：循环试听节奏对上、拖进 Channel Rack / Playlist
- 判定成功：拖拽落地零失败

### 2.3 核心场景（带时间预算）

| # | 场景 | 目标耗时 | 关键路径 |
|---|---|---|---|
| S1 | "给这一刀找一个拔刀声" | ≤ 8s | 点库 → 输入"拔刀" → 悬停试听 3 个 → 拖走 |
| S2 | "同一套里还有别的刀剑声吗" | ≤ 12s | 选中"刀剑动作" → 网格扫视 → 开递归看全库同类 |
| S3 | "新买的素材包入库" | ≤ 30s | 拖文件夹到左栏 → 后台索引 → 边索引边试听 |
| S4 | "交付 20 个给客户" | ≤ 60s | 多选 → 批量导出 → 生成 CSV |
| S5 | "在 Cubase 里干活时找音效" | ≤ 6s | Alt+Shift+S 唤出 → 搜索 → 悬停听 → 拖到工程窗 |

### 2.4 不做清单（明确 out of scope，防止膨胀）

- ❌ 云端素材库、在线商店、账号体系
- ❌ AI 语音生成 / 声音克隆 / 音效合成
- ❌ 多轨音频编辑、降噪、混响处理（要精修请用 RX）
- ❌ 团队协作、共享数据库、权限
- ❌ macOS / 移动端（先 Windows）
- ❌ 自动更新服务（v1 手动下载）
- ❌ 音频指纹/相似推荐（P3 观察）
- ❌ **插件专有容器**：Kontakt（`.nki/.ncw/.nkc`）、UVI（`.ufs`）、Engine、Best Service 等 —— 这些不是音频文件，是给插件读的封装数据；音匣不解析、不伪装支持

> **支持边界（重要）**：音匣只处理"能被本机解码器直接读出 PCM 的音频文件"。
> 判断标准是**文件本身能不能解码**，而不是"它属于哪个素材包"。
> 两个容易混淆的例子：Weaponiser Fully Loaded 看着像插件资源，实际是 6417 个标准 BWF（96 kHz/24 bit），音匣照常索引、试听、拖拽；而 Kontakt 音色库即便里面躺着 `.ncw`，也一样打不开 —— 那需要 Kontakt 本体。

### 2.5 成功标准

| 类型 | 指标 | 目标 |
|---|---|---|
| 北极星 | 单次"找到并取用"耗时 | 中位数 < 15s |
| 体验 | 首次导入到可试听 | < 30s（200 文件） |
| 体验 | 悬停到发声延迟 | < 80ms（不含 140ms 防抖） |
| 体验 | 拖拽落地成功率 | > 99%（FL/S1/Cubase） |
| 工程 | 冷启动 | < 1.5s |
| 工程 | 崩溃率 | < 0.1% 会话 |
| 工程 | 内存（1 万资产） | < 400MB |

## 3. 信息架构

### 3.1 概念模型

```
库 Library（用户拖入的一个根文件夹 = 一个库）
 ├─ 文件夹 Folder（树，对应磁盘真实目录）
 │   └─ 音效 Asset（= 磁盘上的一个文件，唯一真源）
 ├─ 标签 Tag（跨库，多对多）
 ├─ 集合 Collection（手动聚合，可装任意资产，跨库）
 └─ 智能文件夹 Smart Folder（保存的查询条件，动态结果）

全局：最近导入 / 最近试听 / 收藏 / 所有标签 / 搜索结果
```

> **库 ≈ 一个素材包**：产品的心智模型是"买的一个音效包 = 一个库"，而不是"一个硬盘目录 = 一个库"。任意文件夹仍可拖入（兼容散装素材），但默认叙事围绕素材包展开 —— 这也决定了下面"素材包识别"的能力。

三条铁律：
1. **文件真源在磁盘。** 音匣只建索引，不搬文件、不改文件（除非用户显式执行重命名/导出）。
2. **删索引不删文件。** 移除库只是移除索引，磁盘文件原样保留。
3. **文件丢失不静默删除。** 移动硬盘没插时标记 `missing` 灰显，插回来自动恢复。

### 3.3 导航与层级规则

| 当前选中 | 内容区显示 | 说明 |
|---|---|---|
| 库根节点 | 库概览：统计、最近导入、子文件夹卡片 | 第一次点进来不至于空着 |
| 非叶文件夹（默认） | **子文件夹卡片 + 直属音效** | 符合"文件夹里有什么"的直觉 |
| 非叶文件夹（深度开） | 平铺所有后代音效，卡片带相对路径徽章 | 一行看到分类全集 |

### 3.4 空态与异常态（4 种，必须设计）

| 状态 | 文案 | 主操作 |

## 4. 交互规范

### 4.1 选择模型

| 操作 | 结果 |
|---|---|
| 单击卡片 | 单选并聚焦 |
| Ctrl + 单击 | 加入/移出多选 |
| Shift + 单击 | 扩展范围选 |
| Ctrl + A | 全选当前视图结果 |
| 方向键 | 移动选中（网格按行列，列表按行） |
| Esc | 清空选择 → 若在搜索中则先清搜索 |
| 右键点击未选中项 | 先将选择改为该项，再弹菜单 |
| 切换文件夹 | 记住各文件夹的选中态（仅会话内） |

多选拖拽超过 **200 个文件**时提示确认（避免误拖 8 GB 进 DAW）。

### 4.2 悬停试听（核心体验，参数必须可调）

**参数默认值**

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `hover.debounce` | 140 ms | 80–400 | 停留超过才发声，防"机关枪" |
| `hover.fadeIn` | 12 ms | 0–60 | 淡入，防爆音 |
| `hover.fadeOut` | 60 ms | 0–200 | 淡出 |
| `hover.crossfade` | 40 ms | 0–120 | 换目标时的交叉淡化 |
| `hover.startAt` | 从头 | 从头 / 记住上次 | 再次悬停是否续播 |
| `hover.onLeave` | 立即淡出 | 立即 / 播完本遍 | 环境音偶尔需要听完 |
| 窗口失焦 | 立即淡出 | — | 切到 DAW 时不能还在响 |
| `preview.uniformLoudness` | 关 | 开/关 | 响度归一化（约 -16 LUFS） |

**状态机**

| 当前状态 | 事件 | 动作 | 下一状态 |
|---|---|---|---|
| Idle | PointerEnter(A) | 启动 A 的防抖计时 | Armed |
| Armed | 计时到期 | 淡入并循环播放 A | Playing(A) |
| Armed | PointerLeave(A)（未到期） | 取消计时，**不发声** | Idle |
| Armed | PointerEnter(B) | 取消 A，启动 B 的计时 | Armed(B) |
| Playing(A) | PointerEnter(B) | 40ms 交叉淡化 A→B | Playing(B) |
| Playing(A) | PointerLeave 到空白 | 淡出 60ms 停止 | Idle |
| Playing(A) | 窗口失焦 | 20ms 淡出停止 | Idle |
| Playing(A) | 开始拖拽 | 0ms 立即停止 | Idle |
| 任意 | 点击播放按钮 | 固定播放（与 hover 解耦） | Pinned |
| Pinned | 再点播放按钮 / 点别处 | 解除固定并淡出 | Idle |

**卡片反馈（v0.2 起为 DAW 式播放头）**

- 播放中的卡片：波形上叠加 **1.8px 竖线 + 顶部小三角**，每 50ms 刷新，跟着音频走
- **hover 游标线**：鼠标在波形上移动时，一条 45% 透明度的细线跟随鼠标，明确"点这里会从哪里开始"；鼠标离开波形即消失
- 已播放区域：波形左端到播放头之间铺一层 14% 主色
- **点击波形任意位置 = 立刻从那里起播**（不是选中、不是拖拽）：
  - 落在当前循环区间内 → 采样级瞬时 seek，不重开声卡（无延迟）
  - 落在区间外 → 重建循环区间：从点击处循环到**文件末尾**
  - 保证循环段不短于 200ms，避免末尾点击退化成蜂鸣
- **时间轴口径 = 文件真实时间轴**，不是裁剪后的循环区间；所以播放头位置与卡片标的 `2.08s` 始终一致
- **双击卡片 = 固定播放 / 取消固定**（唯一允许"鼠标移开还在响"的入口，卡片左上角显示"固定"标记）
- **单击卡片 = 只做选择**（含 Ctrl / Shift 多选），不启动播放、也不固定 —— 选择是选择，试听是试听，两件事不混在一起
- 鼠标离开 → 立刻淡出停止（未固定时）；单个音频的循环模式不影响这个规则
- Pinned 时左上角出现"固定"标记

**为什么时间轴要按文件真实时间算**：循环会裁掉首尾静音，如果按"裁剪后时间"画播放头，你点在 10s 的地方会跑到别的相对位置上。按真实时间轴，所见即所得 —— 你点哪，就是从哪开始。

**播放头的性能实现（v0.2 实测 20fps → 110fps）**

| 问题 | 修法 |
|---|---|
| `DispatcherTimer(50ms)` 驱动 = 20fps，肉眼卡顿 | 改用 `CompositionTarget.Rendering` 跟渲染帧（实测 ~110fps） |
| 每帧重排 520 根波形柱子 | 几何缓存成 `StreamGeometry` 并 `Freeze()`，只在换文件/尺寸变化时重建 |
| 改 `Width` 推进度条 → 触发整个布局管线 | 改用 `ScaleTransform`，纯合成层，不布局 |
| 时间码每秒更新上百次 → 文字反复排版 | 只在"百分秒"变化时改文本 |

> 试过把刷新锁在 60fps：这台机器渲染节拍约 12ms，隔帧取样反而抖到 42fps，所以最终跟随原生帧率（代价是播放时约占 2% 整机 CPU / 22–31% 单核）。如果之后要做省电档，再加速度上限开关。

### 4.3 循环模式

1. **整段循环**（默认）：从 0 播到文件末尾，**不做任何掐头去尾**
2. **智能循环**（默认关闭，可选）：跳过首尾 ≤50ms 静音，仅推荐给超短素材
3. **交叉淡化**：只在**接缝本身不连续**时自动启用 8ms 淡化；两端本来就落在静音里则保持采样级无缝循环（避免淡化把起音那 8ms 削掉）
4. **单次播放**（不循环）

实现要点：全部在 32-bit float 域做裁剪与包络，96kHz/32bit 素材不做任何降位处理。

> **v0.3 修正**：v0.2 默认开了"智能裁静音"，结果开头有留白的素材听起来像被截短了。现在默认整段播放，裁剪降级为用户可选项 —— 默认行为要可预测，优化必须是"可选择加入"的。

## 5. 视觉系统（含玻璃材质）

### 5.1 五条原则

1. **材质服务于层级**，不是装饰 —— 玻璃只用来做"容器"，不做"主体"。
2. **内容优先** —— 波形和文件名永远是画面里对比度最高的元素。
3. **统一光源** —— 全界面光来自左上，所有边光/高光/阴影方向一致。
4. **克制动效** —— 全部 ≤240ms，只表达因果，不做装饰性动画。
5. **可关闭** —— 任何材质都能一键降级为实心。

### 5.2 三层材质架构

| 层 | 应用 | 实现 | 规格 |
|---|---|---|---|
| **L0 底板** | 窗口整体 | Win11 `Mica`（`DWMWA_SYSTEMBACKDROP_TYPE=2`）；Win10 用 Acrylic 兜底 | 底色 86–92% 不透明，桌面微微透出 |
| **L1 霜面** | 左栏、顶栏、试听条、对话框 | 自绘：下层 1/4 降采样 → `BlurEffect` 18px → 叠色 + 边光 | 模糊 16–24px，色层 62–78%，边光 1px 白 8–14% |
| **L2 液态** | 卡片、按钮、选中态 | 半透明填充 + 指针跟随径向高光 + 内高光 + 上浮 | 白 4–9%，高光 0–18%，阴影三级 |

> ⚠️ **L2 不做模糊**：卡片级模糊既昂贵又无视觉收益。液态感来自高光与边光，不来自模糊。

### 5.3 液态玻璃的五个构成要素

| 要素 | 视觉 | v1 实现 |
|---|---|---|
| 透 Translucency | 背后色块缓慢流动 | 半透明填充 + L1 模糊 |
| 霜 Frost | 背后内容化为色雾 | 降采样模糊 + 饱和度 1.15–1.4 |
| 边光 Edge light | 玻璃"厚度"，顶部一道亮线 | 1px 内描边（深色白 8% / 浅色白 65%） |
| 高光 Specular | 鼠标处一团柔光 | 径向渐变跟随指针，0→0.18，200ms |
| 微折射 Refraction | 边缘轻微放大偏折 | P2 用 HLSL；v1 用内阴影近似 |

### 5.4 性能预算与降级（硬约束）

| 项 | 预算 |
|---|---|
| 单面板模糊重算 | ≤ 1.2 ms |
| 每帧玻璃总开销 | ≤ 2.0 ms（占 16.6ms 的 12%） |
| 同屏模糊面板数 | ≤ 3 |
| 滚动中的列表区 | 不实时模糊，用缓存帧 + 平移补偿 |
| 无 GPU / 远程桌面 | 自动关闭模糊 |

**三档降级**（自动检测 + 手动开关）：全效 → 简化（半透明 + 边光，无模糊）→ 实心（100% 不透明）。

### 5.5 色彩系统

- **Primitive**：`--accent-50..900`、中性 `--n-0..1000`
- **Semantic**：`--bg` `--bg-elev` `--panel` `--text` `--text-2` `--text-3` `--accent` `--on-accent` `--wave` `--wave-played` `--playhead` `--loop-region` `--danger` `--star`
- **Component**：`--card-bg` `--card-hover` `--card-ring` `--tree-active` `--focus-ring`

**派生算法**：内部用 **OKLCH** 生成色阶（HSV 的明度在感知上不均匀，直接 ±10% 会出现跳变）。用户输入仍然是 RGB / HEX / HSV 三向实时互通。

**强制对比度**：正文 ≥4.5:1；`--on-accent` 由相对亮度自动切黑/白（阈值 0.55）；选中态不能只靠颜色（额外 2px 环 + 左侧 3px 条）。

### 5.6 主题系统（RGB / HEX / HSV）

- 输入：三个输入框 + 色轮 + 屏幕吸管，实时互转；接受 `#3B82F6` / `rgb(59,130,246)` / `hsv(217,76,96)`
- 自动派生 12 个语义色与组件色
- 独立可调：主色、波形色、播放头色、循环区色、**玻璃强度（0–100%）**、模糊半径（0–32px）、圆角（0–24px）
- 预设六套：深海青、暮光紫、赛博青柠、暖木、纸白、石墨
- 导入/导出 `.theme.json`；切换主题 180ms 过渡；支持跟随系统

### 5.7 排版与度量

| 项 | 规格 |
|---|---|
| 字体 | `Segoe UI Variable Text` + `Microsoft YaHei UI`；数字/时长用等宽 `tabular-nums` |
| 字号 | 11 / 12（元信息）· 13（正文）· 14（标题）· 20（区块）· 28（空态） |
| 间距 | 4 基准：4 / 8 / 12 / 16 / 24 / 32 |
| 圆角 | 8 控件 / 12 卡片 / 16 面板 / 20 窗口 / 999 胶囊 |
| 阴影 | s1 `0 1px 2px .06` / s2 `0 8px 24px .18` / s3 `0 24px 64px .36` |
| 动效 | hover 120ms / 面板 180ms / 模态 240ms；`cubic-bezier(.2,.8,.2,1)` |

### 5.8 可读性与无障碍

- 玻璃上的文字带 2px 柔和底影，保证任意壁纸下可读
- 焦点环始终可见（2px accent）
- 支持 125% / 150% DPI（全矢量图标）
- 支持系统高对比度模式（自动切实心 + 系统色）

### 6.3 峰值缓存文件格式（`.svpk`）

```
偏移  类型      字段
0     char[4]   'SVPK'
4     u16       version
6     u16       channels
8     u32       sampleRate
12    u32       durationMs
16    u32       levelCount
20    u32       samplesPerPeakL0     (默认 256)
24    u8[8]     reserved
32    ...       逐级峰值数据

每级：u32 sampleStep, u32 pointCount, 然后 pointCount × (i8 min, i8 max)
L0: 256 采样/点   L1: 65536 采样/点
```

- 96 kHz × 2 秒 = 192 000 采样 → L0 750 点（1.5 KB），L1 3 点
- 1 万个文件全部缓存约 15–20 MB，放 `%LocalAppData%\SoundVault\peaks\`
- 缓存可整目录删除并自动重建（版本号不匹配即重建）

### 6.4 扫描与增量

| 阶段 | 策略 |
|---|---|
| 首次枚举 | `EnumerateFiles(RecurseSubdirectories, IgnoreInaccessible)`，边发现边入库 |
| 峰值计算 | 并行工作线程（`min(8, 核数/2)`），按可见性排序 |
| 增量判断 | `(size_bytes, mtime)` 未变 → 跳过；变了 → 重算峰值与信息 |
| 缺失 | 置 `missing=1`，卡片灰显，**不删除** |
| 重连 | 新出现的相同 `(size, duration_ms)` 或同名文件 → 建议批量重连 |
| 续扫 | `scan_state` + 已入库进度，下次启动继续 |

### 6.6 文件名解析（针对你的两个库实测）

实测样例：`001_拔刀相向-叮咚社版权素材.wav`

| 规则 | 正则 / 逻辑 | 结果 |
|---|---|---|
| R1 编号_描述-后缀 | `^(?<index>\d{3})_(?<desc>.+?)(?:-(?<vendor>.+))?$` | index=`001`，desc=`拔刀相向`，vendor=`叮咚社版权素材` |
| R2 UCS 风格 | `^[A-Z]{2,4}-[A-Za-z0-9]+-.+-\d+$` | 拆为 CatID/SubCategory/描述 |
| R3 通用 | 去扩展名、去重尾分隔符 | 兜底 |

- 规则可编辑、可排序、带**实时预览**（只改 `display_name`，不改磁盘文件名）
- 供应商后缀可在设置里维护"剥离列表"（如 `叮咚社版权素材`、`-BOOM Library`）

## 7. 技术架构

### 7.1 技术栈与决策记录（ADR）

| 维度 | 选择 | 备选 | 理由 |
|---|---|---|---|
| 桌面框架 | **.NET 10 + WPF** | Electron / Tauri / WinUI3 | 原生 `DoDragDrop`（DAW 只认真文件）、WASAPI 低延迟、单文件约 70–90 MB、DWM 材质可控。Electron 150 MB+ 且原生拖放需主进程代劳；WinUI3 打包与自绘材质更绕 |
| 音频 | **NAudio + WASAPI 共享模式 + 自写循环 Provider** | MediaPlayer / Web Audio | 20 ms 缓冲、可枚举设备、采样级循环与交叉淡化 |
| 索引 | **SQLite + FTS5** | JSON / LiteDB | 万级查询毫秒级、可增量、可备份迁移 |
| 波形 | **自绘 `DrawingVisual` + 峰值缓存** | 第三方图表库 | 性能与主题完全可控，虚拟化容易 |
| 材质 | **DWM Mica（L0）+ 自绘霜面（L1）+ 高光（L2）** | 整窗 Acrylic | Acrylic 整窗有已知拖动延迟；自绘可控且能逐级降级 |
| 主题 | **DynamicResource + OKLCH 派生** | 多套静态字典 | 用户可自定任意主色，派生 12+ 语义色 |
| 打包 | **单文件自包含 exe** | 依赖运行时安装 | 目标机零依赖、免管理员 |

**分层**

```
SoundVault.App (WPF)  ── Views / ViewModels / Theme / Glass / 交互
   │
   ├── SoundVault.Audio      解码、播放引擎、循环、归一化、设备
   ├── SoundVault.Core       索引、扫描、峰值、元数据、文件名解析、搜索
   └── SoundVault.Interop    DWM、全局热键、拖放辅助、单实例
```

### 7.2 音频管线

```
文件 → Decoder（32-bit float，保持素材原采样率）
     → LoopProvider（裁剪 + 循环 + 交叉淡化）
     → Volume / LoudnessGain
     → WdlResampler（→ 设备采样率 44.1/48k）
     → WasapiOut(Shared, 20ms, 指定设备)
```

- 单实例 `AudioEngine`，hover 与 Pinned 共用同一条输出，避免多路混音叠响
- API：`Play(asset, loopMode, fadeMs)` / `CrossfadeTo(asset, 40ms)` / `Stop(60ms)` / `Seek(ms)`
- 响度归一化：预扫描 `peak_db`，v1 用峰值/RMS 近似；P1 换 ITU-R BS.1770（LUFS）

### 7.3 波形渲染

- 自定义 `WaveformControl`，`OnRender` 用 `StreamGeometry` 画 min/max 包络
- 只画可见区域；纵向 1px 线合并；缓存 `BitmapCache`
- 交互：播放头移动只重绘播放头层（分层 `DrawingVisual`）
- 目标：单帧 ≤2 ms，滚动 60 fps

### 7.5 玻璃渲染实现

| 版本 | 方案 | 说明 |
|---|---|---|
| **v0.1** | DWM `Mica` + 面板半透明叠色 + 1px 边光 + 指针径向高光 | 窗口本身就透出壁纸毛玻璃观感，零性能风险，1 天可成 |
| **v0.2** | `FrostPanel`：下层 1/4 降采样 → `BlurEffect` → 叠色 | 面板之间也有霜面；滚动时用缓存帧 + 平移 |

> 这个分版是刻意的：先保证"好看且流畅"，再追求"更真实的玻璃"。真模糊是最容易把 60fps 搞崩的部分。

### 7.6 单实例 / 热键 / 置顶

## 8. 格式支持矩阵

| 格式 | 容器/编码 | 解码方案 | v1 | 备注 |
|---|---|---|---|---|
| WAV | PCM 16/24/32、float、WAVE_FORMAT_EXTENSIBLE、BWF | 自写 + NAudio | ✅ | 你的库即此格式（96k/32bit/extensible） |
| AIFF / AIFC | PCM、float | NAudio | ✅ | 库里有 20 个 .aif |
| MP3 | MPEG-1/2 Layer III | Media Foundation | ✅ | |
| FLAC | 无损 | Media Foundation（Win10+） | ✅ | |
| M4A / AAC | MP4 容器 | Media Foundation | ✅ | |
| WMA | WMA | Media Foundation | ✅ | |
| OGG | Vorbis | NVorbis | ✅ | 无需系统编解码器 |
| OPUS | Ogg Opus | Concentus | P1 | 纯 C# 解码 |
| CAF / SD2 | Apple | 需外挂 ffmpeg | P3 | Windows 上 DAW 也多不支持 |
| 其他（WavPack、MPC…） | — | 外挂 ffmpeg | P3 | |
| **Kontakt 音色库** | `.nki/.nkm/.ncw/.nkc` | ❌ 不支持 | — | 专有封装，非音频，需 Kontakt 本体 |
| **UVI / Engine / Best Service** | `.ufs/.ews/…` | ❌ 不支持 | — | 同上，加密容器 |
| **Weaponiser 等"插件素材包"** | 常直接给 `.wav` + `.cmd` 安装脚本 | ✅ 按普通 WAV 索引 | — | 素材本身是标准 BWF，可试听可拖拽 |

> 重要边界一：**能试听 ≠ 能拖进 DAW**。DAW 是否支持某格式由 DAW 决定，音匣只负责把原文件交出去。
>
> 重要边界二：**按文件判断，不按素材包判断**。音匣不做"这个库是不是正版插件库"的推理，只看单个文件能否解码 —— 能解码就索引，不能就跳过并说明原因。
